# JobMail AI 字段设计

## 1. 目标

当前 `demo.py` 已经可以提取：

- `dates`
- `times`
- `phones`
- `emails`
- `todos`

但对于“求职邮件助手”来说，这些字段还不够支撑一个更完整的产品体验。

这份文档定义下一轮最值得新增的字段，以及每个字段的作用、来源和落地方式。

## 2. 新增字段清单

| 字段名 | 作用 | 可能来源 | 是否建议优先实现 |
| --- | --- | --- | --- |
| `company` | 识别是哪家公司发来的邮件 | 发件人域名、主题、正文署名 | 是 |
| `position` | 识别对应岗位名称 | 主题、正文中的岗位名 | 是 |
| `deadline` | 提取关键截止时间 | 正文里的日期时间 + 截止关键词 | 是 |
| `interview_mode` | 识别面试形式 | 正文中的“视频/电话/线下”等词 | 是 |
| `contact_person` | 提取联系人 | 正文署名、联系人字段、发件人信息 | 中 |
| `action_suggestion` | 给用户下一步动作建议 | 基于邮件类型和提取结果生成 | 是 |

## 3. 字段逐项说明

### `company`

含义：

- 当前邮件所属公司名称

为什么重要：

- 用户要快速知道这封邮件对应哪个公司
- 后面如果做列表页或看板，`company` 是核心展示字段

可能来源：

1. 发件人邮箱域名
   - `offer@modelworks.ai` -> `modelworks`
2. 邮件主题
   - 例如主题中直接出现公司名
3. 邮件正文署名
   - 例如“XX 公司招聘团队”

第一版建议：

- 先从发件人邮箱域名做一个简化提取

### `position`

含义：

- 这封邮件对应的岗位名称

为什么重要：

- 同一个用户可能同时投多个岗位
- 只有知道岗位名，后续的回复和提醒才有意义

可能来源：

1. 邮件主题
   - `AI产品实习生`
   - `AIGC Product Intern`
2. 正文中岗位描述

第一版建议：

- 先通过主题关键词抽取
- 后面再考虑正文补充识别

### `deadline`

含义：

- 用户必须在某个时间前完成动作的节点

为什么重要：

- 对求职邮件来说，截止时间比普通日期更关键
- 用户真正关心的是“我最晚什么时候要做这件事”

可能来源：

1. 日期 + 时间提取结果
2. 与截止相关的上下文词
   - `前`
   - `截止`
   - `before`
   - `by`

第一版建议：

- 先保留最简单方案：
  - 如果句子里同时出现时间表达和截止关键词，就标记为 `deadline`

### `interview_mode`

含义：

- 面试的进行方式

典型值：

- `video`
- `phone`
- `onsite`
- `unknown`

为什么重要：

- 不同面试形式对应不同准备动作
- 视频面试和线下面试的提醒逻辑不一样

可能来源：

正文关键词：

- `视频面试`
- `电话沟通`
- `线下面试`
- `video interview`
- `phone interview`
- `onsite`

第一版建议：

- 先做关键词映射，不做复杂 NLP

### `contact_person`

含义：

- 这封邮件里最值得记录的联系人

为什么重要：

- 后续回复或跟进时可能会用到

可能来源：

1. 邮件正文中的签名
2. 明确写出的联系人姓名
3. 发件人邮箱前缀

第一版建议：

- 可以先不实现复杂抽取
- 暂时作为低优先级字段

### `action_suggestion`

含义：

- 系统根据邮件类型直接告诉用户“下一步该做什么”

为什么重要：

- 这是项目从“分类工具”升级为“行动助手”的关键字段
- 也是最像产品能力的一部分

建议输出示例：

- `立即确认面试`
- `准备作品集并按时补交`
- `继续等待，无需立刻回复`
- `确认到岗时间并回复联系方式`
- `归档拒信，停止跟进`
- `忽略营销邮件`

第一版建议：

- 不依赖模型
- 直接根据 `label/type` 生成固定建议

## 4. 推荐实现优先级

### 第一优先级

这些最适合下一轮直接在 `demo.py` 里实现：

- `company`
- `position`
- `deadline`
- `interview_mode`
- `action_suggestion`

### 第二优先级

- `contact_person`

## 5. 对 `extract_info()` 的影响

当前返回结构是：

```python
{
    'dates': dates,
    'times': times,
    'phones': phones,
    'emails': emails,
    'todos': todos[:3]
}
```

下一轮建议升级成：

```python
{
    'dates': dates,
    'times': times,
    'phones': phones,
    'emails': emails,
    'todos': todos[:3],
    'company': company,
    'position': position,
    'deadline': deadline,
    'interview_mode': interview_mode,
    'action_suggestion': action_suggestion
}
```

## 6. 最小落地方案

如果只做最小可用版本，建议这样实现：

1. `company`
   - 从发件人域名提取

2. `position`
   - 从主题中的关键词提取

3. `deadline`
   - 从包含“截止/前/by/before”的句子里优先提取

4. `interview_mode`
   - 从正文关键词映射

5. `action_suggestion`
   - 根据分类结果直接生成

## 7. 为什么第三步重要

做到这一步后，你这个项目就不只是：

- 会分类
- 会提取基础文本信息

而是开始具备：

- 面向求职场景的结构化理解
- 对用户下一步行动的明确支持

这会让它更像一个 `AI 产品实习作品`，而不是简单的文本处理 demo。
