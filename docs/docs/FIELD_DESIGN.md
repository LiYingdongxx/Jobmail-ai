# JobMail AI 邮件动作表

## 1. 目标

这份文档定义了：

- 每类求职邮件的业务含义
- 用户收到后最关心的问题
- 系统应该提供的核心帮助
- 是否建议生成回复草稿

它的作用是把项目从“分类脚本”推进成“产品逻辑”。

## 2. 邮件类型与系统动作

| 邮件类型 | 用户最关心的问题 | 系统应提供的帮助 | 是否建议生成回复 |
| --- | --- | --- | --- |
| `interview` | 面试什么时候进行？我需要准备什么？要不要确认参加？ | 提取面试日期、时间、形式；生成确认参加的回复草稿；输出面试准备提醒 | 是 |
| `materials` | 需要补交什么材料？截止到什么时候？ | 提取截止时间、材料清单；生成补交材料回复草稿；提醒优先准备缺失文件 | 是 |
| `follow_up` | 当前进度到了哪一步？我现在要不要继续跟进？ | 识别当前状态；记录预计反馈时间；给出“继续等待/几天后再跟进”的建议 | 视情况而定 |
| `offer` | 是否进入 offer 阶段？何时到岗？还要补什么信息？ | 提取到岗时间、联系电话等确认事项；生成 offer 确认草稿；提醒关键答复节点 | 是 |
| `rejection` | 这次申请是否结束？还需要继续跟进吗？ | 识别为拒信；建议归档；不建议继续消耗精力跟进 | 否 | 可能会发一个争取文件或者是询问邮件
| `spam` | 这是不是对求职没帮助的广告邮件？ | 识别营销信息；降低优先级；建议忽略或过滤 | 否 |

## 3. 每类邮件的详细动作

### `interview`

用户目标：

- 快速确认面试时间和形式
- 避免错过确认截止时间
- 明确需要提前准备的内容

系统动作：

- 抽取 `date`、`time`、`deadline`
- 识别 `interview_mode`，例如视频面试、电话面试、线下面试
- 从正文中提取待办，如“准备自我介绍”“准备项目案例”
- 生成确认参加的正式回复草稿
- 输出行动建议，例如：
  - `立即确认参加`
  - `准备面试材料`
  - `加入日历提醒`

### `materials`

用户目标：

- 明确需要补交哪些文件
- 知道截止时间
- 快速回复招聘方表示会补交

系统动作：

- 抽取 `deadline`
- 识别材料项，如成绩单、在读证明、作品集、英文简历
- 生成补交材料的确认回复
- 输出行动建议，例如：
  - `优先整理作品集`
  - `检查材料格式`
  - `在截止前发送`

### `follow_up`

用户目标：

- 判断当前流程是否还在推进
- 决定自己现在是等待还是继续跟进

系统动作：

- 识别状态表达，例如“仍在评估”“预计下周二前反馈”
- 抽取预计反馈时间
- 不强制生成回复，而是给出策略建议
- 输出行动建议，例如：
  - `继续等待`
  - `3天后再次跟进`
  - `暂不需要操作`

### `offer`

用户目标：

- 明确是否进入 offer 沟通
- 确认到岗时间和联系方式要求
- 尽快给出正式回复

系统动作：

- 提取 `onboard_date`、`deadline`、`contact_info_needed`
- 识别是否要求提供手机号、最早入职时间等信息
- 生成 offer 确认草稿
- 输出行动建议，例如：
  - `确认最早到岗日期`
  - `回复联系方式`
  - `整理个人安排`

### `rejection`

用户目标：

- 快速知道这条投递是否结束
- 避免继续跟进无效机会

系统动作：

- 识别拒信关键词
- 将该机会标记为结束
- 不生成默认回复
- 输出行动建议，例如：
  - `归档该邮件`
  - `停止跟进该岗位`
  - `将精力转向其他岗位`

### `spam`

用户目标：

- 不被无关广告打扰

系统动作：

- 识别营销、折扣、限时促销等词
- 标记为低优先级
- 不生成回复
- 输出行动建议，例如：
  - `忽略`
  - `过滤至低优先级`

## 4. 当前版本与后续改造的关系

当前 `demo.py` 已经覆盖了：

- 邮件分类
- 日期/时间/联系方式/待办提取
- 回复草稿生成

下一轮改造建议围绕这份动作表做 3 件事：

1. 增加字段提取
   - `company`
   - `position`
   - `deadline`
   - `interview_mode`
   - `action_suggestion`

2. 增加类型特定策略
   - `follow_up` 默认不给强回复
   - `rejection` 和 `spam` 不生成回复

3. 增加行动建议输出
   - 让结果不止是“分了类”，还要告诉用户“下一步该做什么”
